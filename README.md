# Отчёт по работе в Jira

Локальное приложение: выгружает активность текущего пользователя в Jira за период и
отдаёт два файла — читаемый HTML-отчёт и заполненный бланк «Отчёт о проделанной работе».

## Запуск

```bash
pip install -r requirements.txt
```

```bash
python app.py
```

Или двойным щелчком по `run.bat`. Откроется `http://127.0.0.1:8765` (если порт занят —
следующий свободный, точный адрес пишется в консоль).

## Что нужно

Python 3.11+ с `requests` и `openpyxl`. Больше ничего: приложение самодостаточно.

Адрес Jira и ключ проекта заданы в `CONFIG` в начале [jira_client.py](jira_client.py).

## Вход

Логин и пароль от Jira вводятся на странице. Пароль живёт только в памяти процесса:
на диск приложение его не пишет и в интерфейсе не показывает. После входа скилл кэширует
cookie-сессию, поэтому пароль не нужен до нажатия «Выйти» — в том числе после перезапуска.
«Выйти» стирает и пароль, и кэш сессии, так что за одним компьютером могут работать разные
люди.

Если удобнее не вводить каждый раз, задайте переменные окружения — тогда приложение
подключится само:

```powershell
[Environment]::SetEnvironmentVariable('JIRA_USERNAME','ulanovvs','User')
[Environment]::SetEnvironmentVariable('JIRA_PASSWORD','***','User')
```

## Что попадает в выборку

Задача берётся, если за период сработал любой из пяти сигналов:

1. вы её создали;
2. вы были её исполнителем и она обновлялась;
3. вы списали в неё время;
4. вы меняли её статус;
5. вы меняли её исполнителя.

Последние два добавлены сверх штатной выборки генератора: перевод чужой задачи в
тестирование с переназначением на тестировщика не оставляет ни одного из первых трёх
следов. Если версия Jira не понимает `CHANGED BY`, приложение откатывается на штатную
выборку и пишет об этом в замечаниях.

## Как считается

- **Отчётные сутки начинаются в 05:00.** Списание 07.08 в 00:16 попадает в рабочий день
  06.08 — так же, как в HTML-отчёте скилла.
- **Начало и окончание работы над задачей** в Jira недостоверны: `started` у worklog это
  момент списания, часто ночью. Поэтому задачи дня выстраиваются подряд от начала рабочего
  дня (по умолчанию 09:00, меняется в форме), а «График рабочего дня» = начало … начало
  плюс сумма списанных часов.
- **«Статус на момент фиксации»** — текущий статус задачи: в истории Jira статусы хранятся
  по-английски, исторический статус потребовал бы словаря перевода.
- **«Блокирующие факторы»** заполняются только у приостановленных задач — комментарием,
  которым пользователь объяснил паузу. Остальные строки пустые, заполняются вручную.
- **Задачи без списанного времени в бланк не попадают** — в нём нет строки без трудозатрат.
  Приложение показывает их отдельным списком после сборки.

## Лист «Все действия»

Бланк показывает только списанное время: одна строка — один worklog. Это малая часть
собранного (за две недели 34 записи из 278). Остальное — переходы статусов, комментарии,
смена исполнителя, создание задач, правки оценок — лежит вторым листом того же файла,
по времени, с фильтром и ссылками на задачи. Время везде переведено в часы.

## Файлы

| Файл | Назначение |
|------|-----------|
| `app.py` | веб-интерфейс и запуск сборки |
| `xlsx_report.py` | заполнение бланка из JSON-выгрузки |
| `jira_client.py` | вход в Jira, кэш сессии, чтение через REST |
| `generate_report.py` | сбор активности за период в нормализованный JSON |
| `render_html.py` | вёрстка HTML-отчёта |
| `assets/report_template.html` | каркас HTML-отчёта |
| `template.xlsx` | бланк отчёта; шапка, подписи и логотип берутся отсюда |
| `test_xlsx_report.py` | проверка раскладки по дням и по графику |
| `reports/` | готовые HTML, JSON и xlsx; не попадает в git |

Три файла — `jira_client.py`, `generate_report.py`, `render_html.py` — и HTML-каркас
перенесены из скилла `jira-browser-workflow` (MIT, Hermes Agent + Nous Research).
Из клиента Jira взята только читающая часть: приложение ничего в Jira не меняет.

`xlsx_report.py` работает и отдельно:

```bash
python xlsx_report.py reports/Jira_ATOM_отчёт_2026-08-03_2026-08-07.json out.xlsx
```

## Известное ограничение

Настройки принтера из бланка (`printerSettings1.bin`) не переживают пересохранение
openpyxl: ориентация и поля сохраняются, привязка к конкретному принтеру сбрасывается.
Логотип и разметка бланка возвращаются в файл после сохранения.
